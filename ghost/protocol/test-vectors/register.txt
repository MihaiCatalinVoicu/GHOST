# Relay key registration conformance vectors (Phase 9 design §4.2–§4.7, §21.2, §22.8.7). One
# script for two replayers:
#   - relay/crates/node/tests/register_vectors.rs replays it against the real relay through
#     Relay::{register_key,store,get,check,list}_at(request, now), Relay::sweep(now) and reopening
#     the same data directory;
#   - the Kotlin ModelRelay of the sync harness replays it in ModelRelayConformanceTest (slice S2).
# relay_semantics.txt keeps the capability semantics and the TTL buckets. A behaviour that is not
# pinned here is not something the model may rely on.
#
# GRAMMAR
# - One operation per line. '#' starts a comment (to the end of the line). Blank lines are ignored.
# - Words are separated by spaces. The first word is the operation. Arguments are key=value words
#   (except the first argument of cap, credential, token and blob, which is a name).
# - "-> <expectation>" ends a line that has an outcome.
# - Names are symbols: [A-Za-z0-9_]+. Capabilities, credentials and tokens share one name space.
#
# Time
#   <time> is <week>+<s> or <week>-<s>: start(week) + s or - s seconds, where
#   start(p) = 345600 + 604800 p (Monday 00:00 UTC), as in redeem.txt. "at <time>" sets the clock;
#   it MAY move back.
#
# Sections
#   relay slot=<n>|slot=none start=<time>
#     a relay with a fresh data directory, the clock at <time> and relay key 32 bytes 0x42. slot=n
#     gives it slot n (the Rust replayer enables redemption for slot n of the committed test
#     Entitlement Schedule of redeem.txt); slot=none gives it no slot. Symbols are forgotten.
#   restart     reopens the same data directory with the same key and slot at the current clock:
#               registrations are kept, the deposit ledger restarts empty.
#   lose-keys   stops the relay, deletes <data-dir>/keys.redb and reopens as restart does: the
#               relay starts with no registration.
#
# Values
#   namespace <N>     SHA-256 of the ASCII name (no declaration).
#   request <R>       the first 16 bytes of SHA-256("ghost/test/request/" || R) (no declaration).
#   blob <B> size=<n> the ASCII name followed by zero bytes up to n bytes (a bucket size).
#   cap <C> v2 ns=<N> week=<p> serial=<S> [quota=<bytes>]
#       a write capability v2 minted with the relay key: 02 || 02 || N || quota(8, BE) (default
#       268435456) || start(p + 1) + 3600 (8, BE) || serial || HMAC-SHA256(key, bytes 0..66),
#       serial = the first 16 bytes of SHA-256("ghost/test/serial/" || S).
#   cap <C> v1 kind=write|read ns=<N> quota=<bytes> expiry=<time>
#       a v1 capability minted with the relay key (the operator CLI's layout).
#   credential <K> kind=read|deposit|fetch slot=<n> ns=<N> secret=<S>
#       a bearer credential v3: 03 || kind (01, 03, 04) || slot || N || SHA-256("ghost/test/secret/"
#       || S). Its verifier is SHA-256(label || slot || N || secret), label "ghost/v1/read-verifier",
#       "ghost/v1/deposit-verifier" or "ghost/v1/fetch-verifier".
#   token <T> from=<C> xor=<i> [mask=<hh>]   C with byte i XORed with mask (default 01).
#   token <T> from=<C> len=<n>               C cut to n bytes, or extended with zero bytes to n.
#
# Operations
#   register ns=<N> period=<p> kind=read|deposit|fetch|none|<n> verifier=<K> cap=<C>|none req=<R>
#            [version=<v>] [cut=namespace|verifier|request]
#     RegisterKey with the verifier of credential K (kind=none is KEY_KIND_UNSPECIFIED, <n> a raw
#     KeyKind value; cut= sends that field one byte short). Expectations, with the capture result:
#       ok valid_until=<time>   OK with valid_until_unix = <time> [ok]
#       wrong_period            OK with WRONG_PERIOD, valid_until_unix = 0 [rejected_period]
#       rejected_capability     PERMISSION_DENIED [rejected_capability]
#       rejected_size           INVALID_ARGUMENT [rejected_size]
#     Every OK answer carries relay_period_id = week(now) and relay_minute = floor(now / 60).
#   store ns=<N> blob=<B> cred=<C> ttl=<s>  -> ok expiry=<time>
#   get blob=<B> cred=<C>                   -> ok uploaded=<time> expiry=<time>   (the bytes are B's)
#   check cred=<C> blobs=<B>,...            -> ok available=<B>,...|available=none
#   list ns=<N> cred=<C>                    -> ok hashes=<B>,...|hashes=none   (cursor start, limit 256)
#     cred= names a capability, a credential or a token. Failure expectations, with the capture
#     result: unauthorized (PERMISSION_DENIED) [rejected_capability], quota (RESOURCE_EXHAUSTED)
#     [rejected_capability], not_found [not_found], rejected_ttl (INVALID_ARGUMENT) [rejected_ttl].
#   record ns=<N> period=<p> kind=<kind> verifier=<K> -> quota=<bytes> serials=<n> valid_until=<time>
#   record ns=<N> period=<p> kind=<kind> verifier=<K> -> none
#     the relay's stored registration of (N, p, kind, verifier of K), live or not.
#   deposits ns=<N> period=<p> verifier=<K> -> used=<bytes>
#     the bytes the deposit ledger charged to that registration (0 without an entry).
#   ledger -> <n>             the deposit ledger holds n entries.
#   sweep -> ok removed=<n>   one relay sweep at the current clock removed n registrations.
#   sweep -> skipped          the clock is below the key store's sweep high-water minute: nothing ran.
#
# RELAY RULES these vectors pin (relay/crates/node/src/register.rs, bearer.rs, relay/crates/storage
# keys.rs, relay/crates/capability DepositLedger)
#   - RegisterKey checks, in order: version 1, a 32-byte namespace and verifier, a 16-byte request
#     id and a kind in {read, deposit, fetch}; a write capability of this relay (v1 or v2, MAC,
#     kind write, the request's namespace, not expired); the period is the capability's week or the
#     next (a v2 capability's week is week(expiry - 3601), a v1 capability's the week of now; the
#     relay's clock never selects it); then it records, in one transaction:
#   - records accumulate per (namespace, period, kind, verifier), valid until start(period + 2) +
#     3600; a new capability credits its quota to an existing record, at most four capabilities per
#     record; a capability registers at most one verifier per (namespace, period, kind), a second
#     one is rejected_capability and records nothing;
#   - a credential v3 authorizes read: list, get, check; deposit: store, check; fetch: list, get;
#     only at a relay whose slot is the credential's, only for the credential's namespace, and only
#     with a live record of its verifier for some period in [week(now) - 3, week(now) + 1];
#   - a store with a deposit credential is charged to the earliest live record (by valid_until)
#     whose allowance still covers it; none: quota, nothing written; the ledger lives in memory;
#   - get with a read or fetch credential answers uploaded_at floored to the start of its ISO week;
#     with a fetch credential also the expiry rounded up to the next ISO week boundary; a
#     capability gets the upload minute and the hour-rounded expiry;
#   - the sweep deletes records with valid_until <= now and never runs below its high-water minute.
