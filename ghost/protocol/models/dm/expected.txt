# The expected result of every ProVerif query of protocol/models/dm (design faza9-dm.md §9.5,
# §16.2 `pq-model`; slice S13). scripts/gates/pq-model.sh runs each model and compares.
#
#   model | token | expected
#
# token: a substring that names exactly one RESULT line of that model's output.
# expected: `true` — ProVerif proves the property; `false` — ProVerif finds the attack, or, for a
# reachability query `event(X)`, finds a trace that executes X. A control (a query that must fail,
# or a mutant model) is how a model shows it can fail at all; a reachability query is how it shows
# its honest flow completes, so that a `true` above it is not vacuous.
# A missing or extra RESULT line, `cannot be proved`, a non-zero exit or a timeout fails the job,
# and so does a .pv or .patch file of the directory that no line lists.
#
# A model named <original>_mutant_<name>.pv is NOT a file: the gate generates it from
# <original>.pv with <original>_mutant_<name>.patch (GNU patch, no fuzz), so a mutant is always
# its original plus one mutation, and a patch that no longer applies fails the job.
#
# Not modelled here (design §22.18): M-4 (a written argument by §9.5's own table), M-5 (EM-1 is
# its only mechanised check), M-8 (vectors, differential tests, fuzzing). A green run is M-1, M-2,
# M-3, M-6 (its step (3) only) and M-7 (its derivation structure only), nothing more.
