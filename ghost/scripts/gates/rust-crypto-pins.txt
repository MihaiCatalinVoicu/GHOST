# Exact versions of the crypto crates, in the lock file and per shipped graph (Phase 8 design
# §14.1, G-11; ADR-22). Read by rust-crypto-pins.sh. The name-based allowlists cannot see a second
# version of a crate; this gate can. Changing a line is a crypto dependency change: review it.
#
#   lock <crate> <version>...
#       Cargo.lock holds exactly these versions of <crate>.
#   graph <package> <targets> <crate> <version> <required|optional>
#       the normal and build edges of <package> for <targets> (comma-separated triples, or "all")
#       reach <crate> only at <version>; "required": they must reach it.
lock rsa 0.9.10 0.10.0-rc.18
lock crypto-bigint 0.5.5 0.7.5
lock blind-rsa-signatures 0.17.2
lock num-bigint-dig 0.8.6
lock ring 0.17.14

# Phase 9 DM cryptography (design faza9-dm.md §2.3, §16.3; ADR-35, ADR-36; evidence V-6). The
# X-Wing stack of ghost-client-dm: libcrux-kem reached only through libcrux_kem::XWing and the
# libcrux_traits slice trait, with an explicit libcrux_ml_kem::mlkem768::validate_public_key call.
# The whole libcrux graph is pinned, not only the four crates §2.3 names as direct, because a
# transitive bump changes verified code; hax-lib is the proof-macro layer they all carry.

# The seal, the wrap envelopes and the derivations. hkdf 0.12.4 is Arti's; 0.13.0 is the DM one.
# x25519-dalek 3.0.0 and curve25519-dalek 5.0.0 are reached only through the dev-only x-wing
